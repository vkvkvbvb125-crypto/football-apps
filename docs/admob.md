# AdMob — 준비만 해둔다 (코드는 1.1)

⚠ **1.0에는 광고가 없다.** 이 문서는 **정식 출시 후 1.1에서 붙일 때** 필요한 것을
미리 모아 둔 것이다. 지금 코드를 늘리지 않는다 — 출시 판정만 커진다.

## 식별자

    앱 ID                     ca-app-pub-8655981738970005~5129291257
    **네이티브 (home_native)**  ca-app-pub-8655981738970005/8011439612

⚠ **배너 단위(`home_banner`)는 AdMob 콘솔에서 삭제했다**(2026-09-21).
  이 문서에 한때 그 ID가 적혀 있었다 — **되살리지 마라.** 배너로 돌아가려면
  단위를 새로 만들어야 하고, 그건 배치를 다시 정한다는 뜻이다.

⚠ **이 둘은 비밀이 아니다.** 앱 바이너리에 그대로 실리고 `app-ads.txt`로 공개되는
값이라 커밋해도 된다. ⚠ 다만 **AdMob 계정의 API 키·결제 정보와는 다르다** —
그건 이 파일에 적지 마라. 「퍼블리셔 ID는 공개, 계정 자격증명은 비공개」가 경계다.

## ⚠ 먼저 알아야 할 것 — AD_ID는 「차단 해제」할 게 없다

빌드 산출물에서 `AD_ID = 0`인 것을 여러 번 확인했는데(vc 12·13),
**막아서가 아니라 아무도 안 넣어서**다:

    app.json의 blockedPermissions = CAMERA · RECORD_AUDIO · FGS_MEDIA_PLAYBACK
    → AD_ID는 애초에 목록에 없다

`react-native-google-mobile-ads`를 넣으면 그 라이브러리가 매니페스트에 AD_ID를
넣어서 **자동으로 1이 된다.**

⚠ **그러니 그날 할 일은 「해제」가 아니라 「넣지 않기」다.** 습관적으로
`blockedPermissions`에 AD_ID를 더하면 **광고가 안 돈다.**
`store-listing.md`의 산출물 권한 검사도 그때 기대값을 바꿔야 한다(0 → 1).

## 할 일 — 순서대로

### ① 라이브러리와 config plugin

    npx expo install react-native-google-mobile-ads

⚠ **`expo install`을 쓴다**(AGENTS.md). 손으로 package.json을 고치면 SDK가 못 박은
버전 결정이 사라진다 — 2026-09-17에 그걸로 네이티브 빌드가 죽었다.

⚠ **네이티브 모듈이다. EAS 빌드가 필요하다** — 개발 클라이언트도 다시 뽑아야 한다.
1.1 작업을 시작하는 날 빌드 한도를 먼저 확인해라(무료 플랜은 매달 초기화).

앱 ID는 `app.json`의 플러그인 설정에 넣는다(라이브러리 문서의 현재 형식을 따른다 —
⚠ **여기 적어 두지 않는다.** 안 해본 설정을 절차에 적으면 그게 근거처럼 읽힌다).

### ② 테스트 광고 ID로만 개발한다

⚠ **개발 중에 실제 단위 ID를 부르지 마라.** 자기 광고를 자기가 보는 것은
AdMob 정책 위반이고, **계정이 정지되면 되돌리기 어렵다.**

구글이 주는 테스트 ID를 쓰고, **실제 ID는 프로덕션 빌드에만** 들어가게 가른다.

⚠ **~~`__DEV__` 하나로 충분하다~~ — 틀렸다. 2026-09-27에 고쳤다.**
  `__DEV__`는 **릴리스 빌드에서 전부 false**다. 그런데 릴리스 빌드에는 두 종류가 있다:

    · 내가 설치해서 판정하는 APK (`preview` · `production-apk`)
    · **비공개 테스트 트랙에 올리는 AAB**

  둘 다 `__DEV__ === false`라 **실제 광고가 나간다.**

⚠ **비공개 테스트가 더 위험하다.** 테스터를 대행으로 모으면(12명 14일 연속 옵트인이
  필요하다 — `store-listing.md`) **관심 없이 누르는 클릭**이 섞인다. 그건
  **무효 트래픽(invalid traffic)**으로 잡히고, AdMob은 그걸 **게시자 책임**으로 본다.
  수익 차감으로 끝나면 다행이고, 계정 정지로 가면 되돌리기 어렵다.

### ②-b 가르는 기준 — 환경변수 하나, **기본이 테스트다**

    실제 ID를 쓴다  ⟺  process.env.EXPO_PUBLIC_ADS === 'real'

    eas.json:  production 프로필만  env: { "EXPO_PUBLIC_ADS": "real" }
               나머지 전부(개발·preview·production-apk·screenshot·closedtest) 없음

⚠ **「없으면 테스트」로 잡은 이유 — 실패하는 방향을 고른 것이다.**
  변수를 빠뜨리면 **프로덕션에 테스트 광고가 나간다** = 수익 0, 정책 위반 0.
  반대로 잡았다면 빠뜨릴 때 **테스트 트랙에 실제 광고가 나간다** = 무효 트래픽.
  둘 중 되돌릴 수 있는 쪽으로 기운다.

⚠ **비공개 테스트용 프로필을 따로 만든다.**
  지금 AAB를 뽑는 프로필은 `production` 하나뿐인데, 그게 실제 ID를 갖는다.
  `closedtest`(extends production, app-bundle, **env 없음**)를 새로 둔다.

⚠ **그리고 「승격(promote)」을 쓰면 안 된다.** Play 콘솔에서 비공개 테스트 트랙의
  AAB를 프로덕션으로 승격하면 **같은 바이너리**가 올라간다 — 테스트 광고인 채로.
  프로덕션에는 `production` 프로필로 **새로 뽑은 AAB를 올린다.**

**기계로 붙드는 법 — 번들 grep 한 줄씩:**

    closedtest AAB  실제 단위 ID 0건   (1건이면 무효 트래픽 위험)
    production AAB  실제 단위 ID 1건   (0건이면 수익이 0이다)

  `store-listing.md`의 번들 검사 절차에 이 두 줄을 같이 돌린다.

### ②-c 테스트 기기 등록 — 자리만 남긴다

⚠ **에뮬레이터는 AdMob이 자동으로 테스트 기기로 본다.** 지금 판정은 에뮬레이터만
  쓰므로(실기기가 없다) 추가 설정 없이 안전하다.

⚠ **실기기가 생기면** `testDeviceIdentifiers`에 그 기기 ID를 넣어야 한다 —
  안 넣으면 실기기 판정에서 실제 광고를 보게 된다. 코드에 **빈 배열과 이유 주석**을
  남겨 두고, 그날 ID만 채운다. 기기 ID는 첫 실행 로그캣에 찍힌다(비밀 아님).


### ③ 배치 — 홈 **공지 아래** 네이티브 카드 하나

    형식     **네이티브 광고** (home_native)   ← 2026-09-21에 배너에서 바꿨다(배너 단위는 삭제)
    자리     홈 화면 **「최근 공지」 아래**, 스크롤 안
    개수     **하나.** 늘리지 않는다
    안 넣는다  **정산 · 회비 · 송금** 화면

⚠ **왜 배너에서 네이티브로 바꿨나 — 자리가 달라진다.**
배너는 **화면에 붙어 따라다니는** 것이고, 네이티브는 **목록의 한 칸**이다.
홈은 「이번주 경기 → 팀 정산 현황 → 최근 공지」로 **읽어 내려가는 화면**이라,
그 흐름의 **끝에 한 칸 더 있는 편**이 붙어 다니는 띠보다 덜 방해한다.

⚠ **「최근 공지」 아래인 이유:** 그게 **홈의 마지막 구역**이다
(HomeScreen 머리말의 구성 순서). 위에 끼우면 사용자가 보러 온 것(경기·정산)을
밀어낸다 — **광고가 목적을 앞지르는 자리**는 만들지 않는다.

⚠ **배너가 아니어서 사라지는 걱정 하나:** 탭 바와 겹치는 문제가 **없다.**
스크롤 안의 한 칸이라 `useTabBarPadding`을 건드릴 일이 없다.
⚠ 대신 **새로 생기는 걱정**이 있다 — 네이티브 광고는 **우리 카드처럼 보인다.**
  · **「광고」 표시가 반드시 보여야 한다**(AdMob 정책이자 법적 요구).
    우리 `SectionCard`와 **구별되게** 만들어라 — 안 그러면 사용자가 공지인 줄 안다
  · 공지가 **0건일 때** 광고만 덩그러니 남는 그림을 확인해라.
    빈 상태 문구(「아직 공지가 없어요」)와 나란히 서는 모양이다

⚠ **정산·회비·송금에 안 넣는 이유는 그대로다.**
· 그 화면들은 **금액을 입력하고 확인하는** 자리다. 오탭 한 번이 광고 클릭이 되고,
  그 사이 입력이 날아가면 **돈 이야기에서 신뢰를 잃는다.**
· 총무가 남의 돈을 다루는 화면이라 **광고가 붙으면 앱이 그 돈으로 장사하는 것처럼
  읽힌다.** 회비 앱에서 가장 비싼 오해다.

### ③-b 안 넣는 형식 — **못 박는다**

    ❌ 전면(Interstitial)      화면을 가로막는다
    ❌ 앱 오프닝(App Open)     열자마자 광고를 본다
    ❌ 보상형 전면(Rewarded Interstitial)

⚠ **이유가 같다: 흐름을 끊는다.** 「경기 만들기」·「투표하기」는 **총무가 약속 시간에
쫓기며 하는 일**이다. 그 사이에 전면 광고를 끼우면 수익보다 **이탈이 크다** —
6명짜리 동호회 앱에서는 한 명이 떠나는 것이 전체의 17%다.
⚠ 앱 오프닝은 더 나쁘다. **앱을 열 때마다** 보이므로 「무거운 앱」이라는 인상이
첫 3초에 박힌다.

### ③-c 나중 후보 — 보상형(Rewarded)

⚠ **지금은 안 넣는다.** 보상형은 **줄 보상이 있어야** 성립하는데 1.1에는 없다.

**생길 조건:** 총무용 **유료 기능**이 생기면 — 그때 「**광고 보고 하루 열기**」를
붙일 수 있다. 예: 통계 내보내기·정산 자동 독촉 같은 것이 유료가 되면,
안 사는 총무에게 **하루짜리 체험**을 광고로 주는 방식이다.

⚠ **보상형 전면(Rewarded Interstitial)과 다르다.** 보상형은 **사용자가 눌러서**
보는 것이고, 보상형 전면은 **들이미는** 것이다. 위 ❌ 목록의 셋째가 그거다.
⚠ 순서: **유료 기능이 먼저다.** 보상이 없는데 광고부터 만들면 줄 것이 없다.

### ④ 정책·양식 — **코드보다 이쪽이 오래 걸린다**

| 무엇 | 왜 |
|---|---|
| **데이터 안전 양식** 수정 | 광고 ID 수집을 **선언해야 한다.** 미선언 상태로 광고를 켜면 정책 위반이다 |
| **처리방침** 수정 | `src/features/auth/terms.ts`가 원본이고 `scripts/build-web-terms.mjs`가 `kickday.app/privacy`를 만든다. ⚠ **웹만 고치면 앱 안 문구와 갈린다** |
| **app-ads.txt** 배포 | `web/app-ads.txt`로 두면 `kickday.app/app-ads.txt`가 된다(web/은 루트가 그대로 경로다). 내용은 AdMob 콘솔이 주는 한 줄 |

⚠ **`app-ads.txt`는 배포가 사용자 몫이다**(`npx wrangler deploy`). 그리고 구글이
크롤링해 갈 때까지 **하루 이상** 걸린다 — 광고를 켜기 **전에** 올려 둔다.

## A1 판정 목록 — **빌드 전에 적는다** (2026-09-27)

⚠ **찍고 나서 기준을 정하면 통과시키는 쪽으로 기운다.** 코드를 쓰기 전에 박아 둔다.

### ⓐ 안전 — 실제 광고가 새지 않는가 (**가장 먼저**)

    ① preview APK 번들에 실제 단위 ID(…/8011439612)가 **0건**
    ② preview APK 번들에 구글 테스트 ID가 **1건 이상**
    ③ 기기에 뜬 광고에 「Test Ad」 표식이 보인다

⚠ ①이 실패하면 나머지 판정을 **하지 마라.** 그 상태로 화면을 만지면
  내 클릭이 실제 광고 클릭이 된다.

### ⓑ 권한 — `AD_ID`가 **1**이 되는가

    aapt2 dump permissions → com.google.android.gms.permission.AD_ID  = 1

⚠ **여태 기대값이 0이었다.** 이제 1이 정상이다 — `store-listing.md`의 금지 권한
  목록에서 `AD_ID`를 빼고 「있어야 한다」로 옮긴다. 0이면 **광고가 안 도는 것**이다.
⚠ 나머지 셋(`FGS_MEDIA_PLAYBACK`·`CAMERA`·`RECORD_AUDIO`)은 **그대로 0**이어야 한다.
  광고 라이브러리가 딸려 오게 하지 않는다.

### ⓒ 설계 ② — 미채움·망 없음·실패일 때 **자리를 접는가**

    ④ 망을 끊고(비행기 모드) 홈 진입 → 광고 카드가 **아예 없다**
       (빈 칸·플레이스홀더·제목만 남는 것 전부 FAIL)
    ⑤ 망을 끊은 채 공지 아래가 **바로 화면 끝**이다
    ⑥ 망을 되살리고 다시 들어가면 카드가 **뜬다**

### ⓓ 설계 ③ — 「광고」 표시가 `SectionCard`와 구별되는가

    ⑦ 「광고」 배지가 **보인다**(가려지거나 잘리지 않는다)
    ⑧ 광고 카드에 **우리 초록 결(SoftTint)이 없다** — 위아래 우리 카드와 나란히 놓고 본다
    ⑨ 광고 위에 **우리 구역 제목이 없다**

### ⓔ 설계 ④ — 공지 0건일 때

    ⑩ 「등록된 공지가 없습니다」 빈 카드 **바로 아래** 광고가 온 그림을 찍는다
    ⑪ 빈 카드와 광고가 **한 덩어리로 안 읽히는지** 눈으로 본다
       (재질이 갈리면 통과. 안 갈리면 간격을 벌린다)

### ⓕ 설계 ⑤ — 다크·라이트

    ⑫ 다크에서 배지·글자 대비
    ⑬ 라이트에서 같은 것
    ⑭ ⚠ **광고 이미지가 테마와 부딪히는지** — 흰 바탕 소재가 다크에서 튀는가.
       우리가 못 정하는 부분이라 「어떻게 보이는지」만 기록한다

### ⓖ 기동·성능 — 새 네이티브 모듈이 붙었다

    ⑮ 크래시 0 (기동 직후 logcat FATAL 0건)
    ⑯ 스플래시 → 홈 도달 시간을 A0와 **같은 방법으로** 재서 비교한다
    ⑰ 홈 스크롤이 걸리지 않는다
    ⑱ ⚠ **메모리** — A0 대비 증가폭. Hermes 회귀를 먼저 걷어낸 이유가 이것이다
       (`adb shell dumpsys meminfo com.kickday.app`의 TOTAL PSS를 양쪽에서 잰다)

⚠ **⑯⑱은 A0 값을 먼저 재 둬야 비교가 된다.** 광고를 넣기 전에 잰다.

**A0 기준선 — 2026-09-27 실측** (에뮬레이터 1080x2400, `a0.apk` vc14)

    기동   am start -W  TotalTime  490 / 439 / 499 ms   (3회)
    메모리 dumpsys meminfo  TOTAL PSS 141,594 KB · TOTAL RSS 248,220 KB

⚠ **이 값은 TeamStart 화면이다**(reviewer 계정에 팀이 0개다). 광고 카드는 **홈**에 있으므로
  A1을 잴 때는 **같은 화면에서** 재야 비교가 된다 — 홈끼리, TeamStart끼리.
  섞어 재면 광고가 올린 것인지 홈이 무거운 것인지 못 가른다.
