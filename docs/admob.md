# AdMob — 준비만 해둔다 (코드는 1.1)

⚠ **1.0에는 광고가 없다.** 이 문서는 **정식 출시 후 1.1에서 붙일 때** 필요한 것을
미리 모아 둔 것이다. 지금 코드를 늘리지 않는다 — 출시 판정만 커진다.

## 식별자

    앱 ID                 ca-app-pub-8655981738970005~5129291257
    배너 (home_banner)    ca-app-pub-8655981738970005/4302285585

⚠ **이 둘은 비밀이 아니다.** 앱 바이너리에 그대로 실리고 `app-ads.txt`로 공개되는
값이라 커밋해도 된다. ⚠ 다만 **AdMob 계정의 API 키·결제 정보와는 다르다** —
그건 이 파일에 적지 마라. 「퍼블리셔 ID는 공개, 계정 자격증명은 비공개」가 경계다.

## ⚠ 먼저 알아야 할 것 — AD_ID는 「차단 해제」할 게 없다

빌드 산출물에서 `AD_ID = 0`인 것을 여러 번 확인했는데(vc 12·13),
**막아서가 아니라 아무도 안 넣어서**다:

    app.json의 blockedPermissions = CAMERA · RECORD_AUDIO · FGS_MEDIA_PLAYBACK
    → AD_ID는 애초에 목록에 없다

`react-native-google-mobile-ads`를 넣으면 그 라이브러리가 매니페스트에 AD_ID를
넣어서 **자동으로 1이 된다.**

⚠ **그러니 그날 할 일은 「해제」가 아니라 「넣지 않기」다.** 습관적으로
`blockedPermissions`에 AD_ID를 더하면 **광고가 안 돈다.**
`store-listing.md`의 산출물 권한 검사도 그때 기대값을 바꿔야 한다(0 → 1).

## 할 일 — 순서대로

### ① 라이브러리와 config plugin

    npx expo install react-native-google-mobile-ads

⚠ **`expo install`을 쓴다**(AGENTS.md). 손으로 package.json을 고치면 SDK가 못 박은
버전 결정이 사라진다 — 2026-09-17에 그걸로 네이티브 빌드가 죽었다.

⚠ **네이티브 모듈이다. EAS 빌드가 필요하다** — 개발 클라이언트도 다시 뽑아야 한다.
1.1 작업을 시작하는 날 빌드 한도를 먼저 확인해라(무료 플랜은 매달 초기화).

앱 ID는 `app.json`의 플러그인 설정에 넣는다(라이브러리 문서의 현재 형식을 따른다 —
⚠ **여기 적어 두지 않는다.** 안 해본 설정을 절차에 적으면 그게 근거처럼 읽힌다).

### ② 테스트 광고 ID로만 개발한다

⚠ **개발 중에 실제 단위 ID를 부르지 마라.** 자기 광고를 자기가 보는 것은
AdMob 정책 위반이고, **계정이 정지되면 되돌리기 어렵다.**

구글이 주는 테스트 ID를 쓰고, **실제 ID는 릴리스 빌드에서만** 들어가게 가른다.
⚠ 가르는 방식은 `__DEV__` 하나로 충분하다 — 환경변수를 새로 만들면
`eas.json`의 `environment`와 얽혀 또 한 겹이 된다.

### ③ 배치 — 홈 하단 배너 하나

    넣는다     홈 화면 **하단** 배너 (home_banner)
    안 넣는다  **정산 · 회비 · 송금** 화면

⚠ **정산·회비에 광고를 넣지 않는 이유는 취향이 아니다.**
· 그 화면들은 **금액을 입력하고 확인하는** 자리다. 오탭 한 번이 광고 클릭이 되고,
  그 사이 입력이 날아가면 **돈 이야기에서 신뢰를 잃는다.**
· 총무가 남의 돈을 다루는 화면이라 **광고가 붙으면 앱이 그 돈으로 장사하는 것처럼
  읽힌다.** 회비 앱에서 가장 비싼 오해다.
⚠ 홈도 **하단**이다. 상단에 두면 「이번주 경기」가 밀려 첫 화면의 목적이 바뀐다.

⚠ 배너가 들어가면 **탭 바와 겹치는지** 봐야 한다 — `useTabBarPadding`이 이미 있고
그 값을 배너 높이만큼 더해야 할 수 있다. **작은 화면(1080×1920)·배율 200%에서
다시 잰다**(키보드 판정과 같은 방식).

### ④ 정책·양식 — **코드보다 이쪽이 오래 걸린다**

| 무엇 | 왜 |
|---|---|
| **데이터 안전 양식** 수정 | 광고 ID 수집을 **선언해야 한다.** 미선언 상태로 광고를 켜면 정책 위반이다 |
| **처리방침** 수정 | `src/features/auth/terms.ts`가 원본이고 `scripts/build-web-terms.mjs`가 `kickday.app/privacy`를 만든다. ⚠ **웹만 고치면 앱 안 문구와 갈린다** |
| **app-ads.txt** 배포 | `web/app-ads.txt`로 두면 `kickday.app/app-ads.txt`가 된다(web/은 루트가 그대로 경로다). 내용은 AdMob 콘솔이 주는 한 줄 |

⚠ **`app-ads.txt`는 배포가 사용자 몫이다**(`npx wrangler deploy`). 그리고 구글이
크롤링해 갈 때까지 **하루 이상** 걸린다 — 광고를 켜기 **전에** 올려 둔다.

## 안 정한 것

· 전면·보상형 광고 — **안 넣는다**가 지금 판단이다. 배너 하나로 시작하고,
  수익이 의미 있으면 그때 다시 본다. ⚠ 전면 광고는 「경기 만들기」 같은 흐름을
  끊어서, 6명짜리 동호회 앱에서는 비용이 수익보다 크기 쉽다.
· 유럽 사용자(GDPR/UMP 동의 창) — 한국 대상 앱이라 **1.1 범위 밖**으로 둔다.
  ⚠ 스토어는 전 세계에 열리므로, **유럽에서 설치되면 동의 창이 필요하다.**
  출시 국가를 한국으로 제한하는지 먼저 정해야 이 답이 정해진다.
