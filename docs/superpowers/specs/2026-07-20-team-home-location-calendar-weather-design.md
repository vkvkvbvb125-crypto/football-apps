# 팀 대표 지역 + 캘린더 전체 날짜 날씨 표시 설계

## 배경

지금 일정 캘린더는 경기가 등록된 날짜에만 날씨(날짜 원 배경 색조)를 보여준다. 아직 경기를 안 잡은 날에도 날씨를 미리 보여줘서, 총무가 "이 날은 비 오니까 실내 고려, 저 날은 맑으니 야외로" 판단하고 경기를 잡을 수 있게 한다. 경기 없는 날의 날씨는 팀이 미리 설정해둔 "대표 지역" 좌표 기준으로 조회한다.

## 1. 데이터 모델

`teams` 테이블에 컬럼 4개 추가(경기 장소와 동일한 패턴):

```sql
alter table teams
  add column home_place_name text,
  add column home_address text,
  add column home_latitude double precision,
  add column home_longitude double precision;
```

## 2. 대표 지역 설정 UI

`TeamHomeScreen.tsx`의 총무 전용 섹션(기존 초대코드 카드 아래)에 "팀 대표 지역" 카드를 추가한다. 이미 만든 `PlaceSearchModal`(카테고리 칩 + 검색, 위치 기반 정렬)을 그대로 재사용한다. 대표 지역이 없으면 "대표 지역을 설정해주세요" 안내 문구, 설정돼 있으면 장소명을 보여주고 탭하면 다시 검색해서 바꿀 수 있다. 일반 멤버에게는 이 카드 자체가 보이지 않는다(기존 초대코드 카드와 동일하게 `isAdmin` 조건).

대표 지역을 바꾸면 팀 정보(`activeTeam.team`)를 다시 불러와야 하므로, 저장 후 `teamStore`의 팀 목록을 재조회한다.

## 3. 캘린더 날씨 로직 변경

`AttendanceScreen.tsx`의 `calendarWeather` 계산을, "이 달에 표시된 경기들"이 아니라 **오늘부터 10일간의 모든 날짜**를 순회하는 방식으로 바꾼다. 각 날짜마다:

1. 그 날짜에 경기가 있으면(좌표 있는 경기) 그 경기의 좌표로 조회 — 지금과 동일.
2. 경기가 없으면 팀 `home_latitude`/`home_longitude`가 설정돼 있을 때만 그 좌표로 조회.
3. 경기도 없고 대표 지역도 없으면 그 날짜는 조회하지 않는다(날씨 표시 안 함 — 지금과 동일한 "표시 안 함" 기본값).

이 계산은 월 이동(`monthOffset`)과 무관하게 항상 "오늘" 기준으로 이루어지므로, 다른 달로 이동해도 그 달 안에 오늘+10일 범위가 겹치는 날짜엔 자연스럽게 표시된다(예: 오늘이 7/25면 8/1~8/4도 표시 대상).

같은 날짜에 경기가 여러 개일 가능성은 낮지만, 있다면 첫 번째 경기의 좌표를 쓴다.

## 범위 밖

- 날씨 조회 캐싱 — 이 기능으로 화면당 최대 10건의 추가 조회가 발생하지만(오늘+10일, 경기 없는 날마다 팀 대표지역으로 조회), 개인 프로젝트 규모에서는 감내하고 이번엔 캐싱을 다루지 않는다.
- 대표 지역이 여러 개(예: 요일별로 다른 구장) — 팀당 대표 지역 하나만 지원한다.
- 팀원(비총무)이 대표 지역을 제안/투표하는 기능.
