# 멤버 관리 + 총무 위임 설계

## 배경

스펙 문서 "6단계: 멤버 관리 + 총무 위임"이 아직 구현 안 되어 있었다. `useTeamStore`에 `members` 목록은 이미 조회되고 있지만(분배 기능 등에서 이름 조회용으로만 사용), 멤버를 보거나 관리하는 화면 자체가 없었다. 자리 비우신 동안 이어서 진행하며 아래 결정들을 내 판단으로 정했다.

## 결정한 것들 (근거 포함)

1. **멤버 여러 명이 동시에 총무일 수 있음 (기존 DB 제약과 동일)**, "위임"은 다른 멤버를 총무로 추가 임명하는 것이지 본인이 총무에서 내려오는 게 아님.
   - 근거: `team_members.role`에 총무를 1명으로 제한하는 DB 제약이 원래 없었고(체크 제약은 'admin'/'member' 값만 제한), 스펙 문구 "마지막 총무는 위임 없이 탈퇴 불가"도 총무가 여러 명일 수 있다는 걸 전제로 한 문구라고 해석했다.
2. **"탈퇴(본인이 팀 나가기)" 기능은 이번에 안 만듦.** 대신 "마지막 총무 보호"는 **총무가 다른 총무를 내보내기(추방)할 때**만 적용 — 유일한 총무를 추방하려 하면 막는다.
   - 근거: 이 세션에 "팀 나가기" 플로우 자체가 없어서, 없는 기능의 예외 케이스까지 만드는 건 범위가 너무 넓어짐. 스펙에 있는 문구 중 지금 실제로 존재하는 액션(총무의 멤버 추방)에만 안전장치를 적용했다.
3. **UI 위치: 팀 홈 화면에 "멤버" 미리보기 섹션(인원수) + "전체보기" 모달**, 기존 공지사항 섹션과 동일한 패턴.
   - 근거: 이미 확립된 미리보기+전체보기 모달 패턴을 그대로 재사용하는 게 제일 자연스럽고 일관적.
4. **실력태그 변경: 총무가 멤버 칩을 탭하면 상→중→하→미지정 순으로 순환.**
   - 근거: 분배 기능의 실력태그 밸런싱에 이미 쓰이는 값이라(상/중/하/null) 이 3+1개 상태를 그대로 순환시키는 게 제일 간단함.
5. **총무 임명/추방 액션은 본인 행에는 안 보이게 함** (자기 자신을 추방하거나 스스로 총무 임명하는 건 의미 없음).

## 검증 방법

`npx tsc --noEmit` + 수동 확인 (사용자 복귀 후):
1. 팀 홈 화면에 "멤버" 섹션(인원수)이 보이는지, "전체보기"로 전체 목록이 열리는지
2. 총무 계정에서 다른 멤버의 실력태그 칩을 탭하면 상→중→하→미지정으로 바뀌는지
3. 총무 계정에서 다른 멤버를 "총무 임명"하면 그 멤버도 총무 배지가 붙는지
4. 총무가 2명 이상인 상태에서 한 명을 "내보내기"하면 정상적으로 추방되는지
5. 총무가 1명뿐인 상태에서 그 총무를 내보내려고 하면(다른 총무 계정이 있다면) 막히는지 — 이 케이스는 총무가 2명 이상 있어야 테스트 가능
6. 일반 멤버 계정으로 보면 실력태그 변경/임명/추방 버튼이 안 보이는지
