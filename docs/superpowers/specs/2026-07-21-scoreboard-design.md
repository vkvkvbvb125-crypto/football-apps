# 스코어보드 설계

## 배경

경기운영 탭에 "분배"/"타이머" 두 개의 뷰가 있고, 스펙 문서상 남은 항목 중 "스코어보드(라운드 내 간단 탭카운터)"를 이번에 추가한다. 사용자가 자리를 비운 상태에서 진행 승인을 받을 수 없어, 아래 결정들은 기존 패턴과 스펙 원문을 기준으로 판단해서 정했다. 확인 후 다르게 하고 싶은 부분은 언제든 말씀해달라.

## 결정한 것들 (근거 포함)

1. **팀 개수: 2팀 고정 (A팀/B팀)**, 분배 기능의 가변 팀 개수(2~5팀)와 연동하지 않음.
   - 근거: `TimerPanel`이 이미 특정 경기와 연결되지 않은 완전히 독립적인 로컬 상태이고(어떤 경기가 "진행 중"인지 알 방법이 없음), 스코어보드도 같은 성격의 도구라 특정 경기의 team_count를 참조할 근거가 없다. 스펙 원문도 "라운드 내 간단 탭카운터"로 단순하게 정의되어 있어 2팀 탭카운터가 가장 무난하다.
2. **위치: "분배"/"타이머" 옆에 "스코어" 3번째 뷰 토글로 추가**, 별도 화면이나 탭은 만들지 않음.
   - 근거: 기존 뷰 토글 UI 패턴을 그대로 재사용하는 게 가장 자연스럽고 적은 변경으로 됨.
3. **완전 로컬 상태, DB 저장 안 함** (타이머와 동일한 패턴).
   - 근거: 스펙의 "오프라인 대응 필수" 원칙과 기존 타이머 구현 패턴을 그대로 따름. 경기 다시 불러왔을 때 점수가 유지될 필요는 우선순위가 낮다고 판단.
4. **UI: 팀당 큰 숫자 + "+1"/"-1" 버튼, 전체 초기화 버튼 하나.**
   - 근거: 라운드 중 빠르게 탭해야 하므로 버튼은 크고 단순하게, 세트/쿼터 개념은 넣지 않음(스펙에 "라운드 내" 라고만 명시, 별도 요구 없음).

## 검증 방법

`npx tsc --noEmit` + 수동 확인 (사용자 복귀 후):
1. 경기운영 → "스코어" 탭에서 A팀/B팀 점수가 0부터 시작하는지
2. +1/-1 버튼이 정상 동작하고 0 밑으로 안 내려가는지
3. 초기화 버튼으로 둘 다 0으로 돌아가는지
4. 다른 뷰(분배/타이머)로 갔다가 돌아와도 점수가 유지되는지 (같은 화면 인스턴스가 유지되는 한)
