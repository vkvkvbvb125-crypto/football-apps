# 게시판 개편 — 댓글·고정·수정·접기

2026-08-15

## 배경

지금 게시판은 글을 쓰고, 좋아요를 누르고, 지우는 것까지만 된다. 댓글은 테이블(`post_comments`)과
개수 표시만 있고 화면이 없어서, 글에 답을 달 방법이 없다. 팀 안에서 오가는 이야기가 한 방향으로만
흐른다.

참고한 화면이 있으나 **기능만 가져오고 시각 디자인은 그대로 옮기지 않는다.** 참고에서 아이콘 4개를
늘어놓은 자리는 이 앱이 이미 쓰는 `⋮` 팝오버 관례로 바꾼다(아래 "참고와 다르게 가는 지점").

## 범위

**넣는 것**

- 댓글: 목록 · 작성 · 삭제
- 글 고정(핀) — 총무만
- 글 수정 — 작성자 본인만
- 긴 글 접기/펼치기

**빼는 것과 이유**

| 뺀 것 | 이유 |
|---|---|
| 공유 | 팀 안에서만 보이는 글이다. 밖으로 내보낼 대상이 없다 |
| 대댓글 | `post_comments`가 평면이고 참고 화면에도 없다. 스키마를 바꿀 이유가 없다 |
| 댓글 좋아요 | 요청에 없다 |
| @멘션 | 설계는 따로 확정돼 있다. 게시판이 자리 잡은 뒤 그 위에 얹는다 |

## 데이터

### 마이그레이션 `supabase/migrations/20260815_board_pins_edit.sql`

```sql
create table if not exists public.post_pins (
  post_id uuid primary key references public.posts(id) on delete cascade,
  pinned_by uuid not null references auth.users(id) on delete cascade,
  created_at timestamptz not null default now()
);

alter table public.posts add column if not exists updated_at timestamptz;
```

RLS — `post_pins`: select는 그 팀 팀원, insert·delete는 그 팀 총무만.

### 고정을 왜 별도 테이블로 두는가

`posts.is_pinned` 컬럼을 두면 총무에게 `posts` update 권한을 열어야 하고, 그러면 총무가 남의 글
**본문까지** 고칠 수 있게 된다. 앱에서 안 보여줄 뿐 API로는 가능하다. 컬럼 단위로 막으려면
`BEFORE UPDATE` 트리거를 심어야 하는데, 이 코드베이스에 없던 개념이다.

테이블을 나누면 "총무는 고정만 할 수 있다"가 데이터 모델로 보장된다. 트리거가 필요 없고,
`posts` 정책은 손대지 않는다. 조회 비용도 사실상 없다 — `fetchPosts`는 이미 좋아요·댓글·프로필을
병렬로 모아 와서 화면에서 합치는 구조라, 같은 자리에 쿼리 하나만 더 얹으면 된다.

`updated_at`은 nullable로 둔다. null이면 한 번도 안 고친 글이다. `created_at`과 비교하는 방식은
초 단위 오차로 갓 쓴 글이 "수정됨"으로 표시될 수 있다.

## 서비스 (`boardService.ts`)

`Post`에 `isPinned: boolean`, `updatedAt: string | null` 추가.

| 함수 | 비고 |
|---|---|
| `updatePost(postId, { body })` | `updated_at`을 함께 쓴다. 카테고리는 안 바꾼다 |
| `setPin(postId, userId, pinned)` | `post_pins` insert / delete |
| `fetchComments(postId)` | 펼칠 때만 호출 |
| `createComment(postId, authorId, body)` | |
| `deleteComment(commentId)` | 권한은 RLS가 막는다 |
| `sortPosts(posts)` | 고정 먼저 → 최신순 (순수 함수, 검증 대상) |

`fetchPosts`는 기존 3개 병렬 쿼리에 `post_pins` 하나를 더하고, 마지막에 `sortPosts`를 태워
정렬된 목록을 돌려준다. 정렬을 화면이 아니라 여기서 하는 이유는 목록을 쓰는 곳이 둘이기
때문이다(게시판, 팀 홈의 최근 게시글). 순수 함수로 떼어 둔 것은 검증하기 위해서다.

**댓글은 목록에서 미리 안 불러온다.** 글 100개의 댓글을 통째로 끌고 오면 대부분 펼쳐보지도 않을
것에 돈을 쓴다. 목록에는 지금처럼 개수만 집계하고, 펼칠 때 그 글 것만 가져온다.

## 화면

### 파일 구성

`BoardPanel.tsx`는 지금 326줄인데, 수정·고정·접기·댓글을 다 넣으면 600줄을 넘긴다. 셋으로 나눈다.

| 파일 | 하는 일 | 아는 것 |
|---|---|---|
| `BoardPanel.tsx` | 목록 · 필터 · 작성창. 글 데이터 소유 | 서비스 호출 |
| `PostCard.tsx` | 글 하나 그리기, 액션은 콜백으로 위임 | 콜백만. 서비스 모름 |
| `PostComments.tsx` | 펼쳤을 때 댓글 목록 · 입력 | 자기 글의 댓글만 |

댓글 데이터는 `PostComments`가 직접 들고 로드한다. 부모가 전부 소유하면 `BoardPanel`이 다시
부풀고, 어차피 펼친 글에서만 쓰는 데이터다. 개수 변화만 `onCountChange(delta)`로 위에 알려
목록의 댓글 수를 맞춘다.

작성자 이름·사진은 세 곳 모두 `resolveAuthor(post, members)`를 쓴다 — 글에 박힌 값은 불러온
시점의 복사본이라 프로필을 바꿔도 안 따라온다.

### 참고와 다르게 가는 지점

| 참고 화면 | 이 앱 |
|---|---|
| 우상단에 접기·핀·수정·삭제 아이콘 4개 | `⋮` 팝오버 하나에 수정 / 고정 / 삭제. 권한 없는 항목은 안 그림 |
| 접기 아이콘 | 본문 아래 `더보기` 텍스트 |
| 주황 "운영공지" 배지 | 초록 계열 핀 배지 |

`⋮` 팝오버는 일정 화면이 이미 쓰는 방식이라 앱 안에서 일관된다. 아이콘 4개는 카드 머리를 시끄럽게
만든다.

### 세부 동작

- **접기**: 본문 `numberOfLines={6}`. `onTextLayout`으로 실제 6줄을 넘길 때만 `더보기`를 노출한다.
  안 넘치는 글에도 "더보기"가 붙는 것이 이 기능에서 제일 흔한 실수다.
- **수정**: 카드 안에서 인라인 편집(본문만). 별도 모달로 띄우면 읽던 자리를 잃는다.
  수정한 글은 시간 옆에 `· 수정됨`.
- **고정**: 목록 맨 위로 올리고 좌상단에 핀 배지. 개수 제한은 두지 않는다(총무만 할 수 있다).
- **댓글**: 푸터의 댓글 아이콘·개수를 펼침 토글로 바꾼다. 여러 글을 동시에 펼칠 수 있다.
  삭제 버튼은 내 댓글이거나 총무일 때만 그린다(RLS와 같은 규칙이라 화면과 서버가 어긋나지 않는다).

## 알림

댓글이 달리면 **글쓴이에게만** 보낸다.

```
notifyTeam(teamId, '<이름>님이 댓글을 남겼어요', 본문 미리보기, undefined, [글쓴이 userId])
```

내가 내 글에 달면 안 보낸다. `kind`는 넘기지 않는다 — 나에게 직접 온 반응이라 끄고 켜는 종류로
두지 않는다.

**대상은 user_id 합집합으로 모아 중복을 없앤 뒤 한 번만 보낸다.** 지금은 대상이 글쓴이 하나뿐이라
의미가 없어 보이지만, 멘션을 얹으면 "댓글에서 글쓴이를 멘션"할 때 같은 사람에게 두 번 울린다.
그때 고치는 것보다 자리를 미리 잡아 두는 편이 싸다.

## 에러 처리

낙관적 반영은 **좋아요만** 유지한다. 댓글·수정·고정은 서버 왕복 뒤에 반영한다 — 되돌리기가
좋아요보다 지저분하고, 실패했는데 화면에 남아 있는 편이 더 나쁘다.

| 실패 | 처리 |
|---|---|
| 댓글 작성 | 입력 내용을 **지우지 않고** 유지 + 알림창. 쓴 걸 날리는 게 최악이다 |
| 댓글 로드 | 그 자리에 `댓글을 불러오지 못했어요 · 다시` 한 줄 |
| 수정 · 고정 · 삭제 | 알림창, 목록은 그대로 |
| 알림 전송 | 조용히 무시. 댓글은 이미 달렸고, 알림 실패가 댓글 실패처럼 보이면 안 된다 |

## 검증

`scripts/board.check.ts` — `sortPosts` assert 체크. Node 24가 타입을 벗겨내므로
`node --experimental-strip-types`로 바로 돌아간다(새 의존성 없음).

- 고정된 글이 항상 위
- 같은 그룹(고정끼리 · 일반끼리) 안에서는 최신순
- 고정한 시각은 순서에 영향을 주지 않는다
- 고정이 하나도 없을 때 기존 순서와 같다

실물 확인 항목:

- 6줄 넘는 글에만 `더보기`가 붙는다
- 총무가 아닌 사람에게 고정 항목이 안 보인다
- 남의 글에 수정 항목이 안 보인다
- 댓글을 달면 목록의 개수가 따라 바뀐다
- 내 글에 내가 댓글을 달면 알림이 안 온다

## 적용

마이그레이션 파일만 저장소에 추가한다. 원격 DB 실행은 하지 않는다 — 평소 하던 방식대로 직접
돌린다.
